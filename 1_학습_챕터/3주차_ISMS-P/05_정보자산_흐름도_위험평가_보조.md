> [!IMPORTANT]
> **🎯 이 챕터 핵심 3줄**
> 1. 신입의 일은 위험관리의 앞부분, 즉 빠짐없는 자산 목록과 정확한 흐름이다. 여기가 틀리면 뒤의 위험평가가 전부 틀린다.
> 2. 개발·테스트, 클라우드, 백업, 보안시스템, 외주 PC, 제3자 제공받은 정보처럼 자주 빠지는 자산을 구성도·콘솔과 대조해 찾고, 흐름도는 실제와 대조해 현행화한다.
> 3. 위험도 점수·DoA·위험 수용·보안등급 확정은 PM 방법론과 고객사 경영진 승인 대상이다(엘지유플러스 개발·검수 환경 사례).

---

## 1. 학습 목표

1. 인증범위 내 정보자산을 분류기준에 따라 빠짐없이 식별하고 목록을 작성할 수 있다.
2. 서비스 단위 개인정보 흐름표·흐름도를 작성하고 실제 처리와 대조해 현행화할 수 있다.
3. 위험평가에서 신입이 맡는 보조 업무(자산·위협·취약점 정리, 평가표 작성)를 수행할 수 있다.

---

## 2. 현장 비유와 기초 개념

> [!TIP]
> 🏗️ 💡 현장 비유: 정보자산 목록은 **집의 물건 목록**, 흐름도는 물건이 집 안팎을 오가는 동선도, 위험평가는 "도둑이 들면 어디가 제일 위험한가"를 따지는 일이다. 목록에 없는 방은 잠글 생각도 못 한다.

> [!NOTE]
> 📌 **기초 개념 짚기**
>
> ISMS-P 1.2(위험 관리) 분야는 정보자산 식별(1.2.1), 현황 및 흐름분석(1.2.2), 위험 평가(1.2.3), 보호대책 선정(1.2.4)의 4개 항목이다. 위험평가는 관리체계 전 영역에 대해 **연 1회 이상** 하고, 수용 가능한 위험은 경영진 승인을 받는다.
> - 근거: ISMS-P 인증기준(별표 7) 1.2.1~1.2.4[^isms7], 인증기준 안내서[^ig121] [^ig123]

    B --> C["1.2.3 위험 평가<br/>(어디가 위험한가)"]
    C --> D["1.2.4 보호대책 선정"]

시험에서는 "자산 식별 → 위협·취약점 → 위험도 → 보호대책"이라는 순서를 배웠습니다. 현장에서 신입이 하는 일은 **그 순서의 앞부분(빠짐없는 목록과 정확한 흐름)**이고, 여기가 틀리면 뒤의 위험평가가 전부 틀립니다.

> ✅ **2절 한 줄 정리**: 위험 관리 4개 항목 중 신입은 자산 목록과 흐름을 맡고, 이 앞부분의 정확도가 위험평가 전체를 좌우한다.

| 근거 | 키워드 | 출처 |

| ② 1.2.2 현황 및 흐름분석 | 흐름도, GAP 분석표 | [^ig122] |
| ③ 1.2.3 위험 평가 | 연 1회 이상, DoA, 경영진 보고 | [^ig123] |
| ④ 1.2.4 보호대책 선정 | 처리 전략, 이행계획 | [^ig124] |
| ⑤ 안전성 기준 제4조제1항제15호 | 위험 분석 및 관리 | [^safe4] |
| ⑥ 영향평가 수행안내서 | 흐름표·흐름도 작성 | [^piag] |

**🔎 번호별 보충 설명** (요지 / 쉬운 풀이: 현장에서 확인할 것)

- ① 요지: 분류기준 수립, 범위 내 **모든** 자산 식별, 법적 요구사항·업무 영향을 고려한 중요도·보안등급, 정기 조사로 **최신** 유지. 클라우드는 특성을 반영한 분류기준(가상서버, 오브젝트 스토리지 등)
  - 풀이: 자산 유형: 서버, 데이터(DBMS), 응용프로그램, SW, 네트워크, 보안시스템, PC, 정보, 설비, 시설 등. 보안등급은 기밀성·무결성·가용성·법적 준거성 등
- ② 요지: 정보서비스 현황·업무 흐름 문서화, 개인정보 처리 현황과 흐름을 **흐름도 등**으로 문서화, 주기적 검토로 최신성 유지. 현황분석은 **GAP 분석표**로 인증기준과 운영현황 비교
  - 풀이: 개인정보 흐름도는 수집·보유·이용·제공·파기 단계별 흐름을 한눈에 보이게 한 개념도. 안내서 예시는 영향평가 수행안내서 양식을 인용
- ③ 요지: 위험평가 방법 정의(베이스라인, 상세위험 분석, 복합, 위협·시나리오 기반 등), 수행인력·기간·대상·방법·예산을 담은 위험관리계획 매년 수립, **연 1회 이상** 및 중요한 변화 시 평가, 목표 위험수준(DoA) 설정, 경영진 보고
  - 풀이: 위험관리 수행인력에 외부 전문컨설턴트도 참여 가능 (이해관계자 참여 필요)
- ④ 요지: 위험 처리 전략(감소·회피·전가·수용), 우선순위·일정·담당·예산을 포함한 이행계획, 경영진 승인
  - 풀이: 신입은 이행계획 표 초안
- ⑤ 요지: 내부 관리계획에 "위험 분석 및 관리에 관한 사항" 포함
  - 풀이: ISMS-P 위험평가 결과가 내부 관리계획 위험 분석과 연결
- ⑥ 요지: 흐름표(수집·보유이용·제공파기)와 흐름도 작성 방법, 범례(온라인 실선·오프라인 점선 등)
  - 풀이: 4주차-05에서 자세히. 여기서는 같은 양식 재사용

> ✅ **3절 한 줄 정리**: 1.2.1~1.2.4는 자산 식별·흐름분석·위험평가·보호대책을 정하고, 흐름표·흐름도는 영향평가 양식을 재사용하며, 결과는 내부 관리계획 위험 분석과 연결된다.

### 단계별 설명

| 단계 | 결과물 | 소요 (예시) |
|---|---|---|
| 1. 자산 식별 | 정보자산 목록 | 1주 |
| 2. 등급 초안 | 보안등급 초안 | 2~3일 |
| 3. 흐름 분석 | 흐름표·흐름도 | 1주 |
| 4. 위협·취약점 | 위험 식별표 | 2~3일 |
| 5. 이행계획 초안 | 이행계획 초안 | 2일 |

**🔎 번호별 보충 설명** (하는 일 / 입력 자료)

- 1. 자산 식별
  - 하는 일: 목록 작성, 누락 점검
  - 입력 자료: 시스템 목록, 구성도, 클라우드 콘솔 캡처
- 2. 등급 초안
  - 하는 일: 분류기준에 따른 C·I·A·법적 준거성
  - 입력 자료: 분류기준
- 3. 흐름 분석
  - 하는 일: 서비스별 흐름표·흐름도, 실제 대조
  - 입력 자료: DB 정의서, 인터페이스 정의서, 인터뷰
- 4. 위협·취약점
  - 하는 일: 갭 분석·점검 결과를 위험 식별표로
  - 입력 자료: 갭 분석표
- 5. 이행계획 초안
  - 하는 일: 보호대책·우선순위·일정·담당·예산 표
  - 입력 자료: 위험평가 결과 (PM)

| ③ 업무 PC 자산 정보 수집 (샘플) | PowerShell |
| ④ 설치 프로그램 확인 (내부정보 유출통제 SW 존재 확인) | 설정 / PowerShell |

**🔎 번호별 보충 설명** (도구·경로 / 방법)

- ① 경로: PowerPoint SmartArt 또는 Visio(보유 시), 또는 Mermaid를 지원하는 편집기
  - 방법: 범례(온라인 실선·오프라인 점선·암호화 굵은 선)를 먼저 정하고 시작
- ② 경로: Excel `=COUNTIF(자산목록!C:C, 구성도목록!B2)=0`
  - 방법: 구성도·클라우드 목록에는 있는데 자산 목록에 없는 항목 표시
- ③ 경로: PowerShell `Get-ComputerInfo -Property CsName, OsName, OsVersion`
  - 방법: 고객사 승인하에 담당자가 실행, 결과만 수령
- ④ 경로: 설정 → 앱 → 설치된 앱, 또는 `Get-Package`
  - 방법: DLP·매체제어 SW 설치 여부 → 자산 누락 확인

</details>

> ✅ **4절 한 줄 정리**: 범위 확인 → 분류기준 → 자산 식별·누락 점검 → 등급 초안 → 흐름표·흐름도 대조 → 위협·취약점 정리 → PM 위험평가 → 이행계획 초안 순서로 보조한다.

- 보안등급
  - 🙋 신입: 기준에 따른 초안
  - 🧑‍💼 PM·선임: 등급 기준 해석
  - 🏢 고객사: **등급 확정**
- 흐름 분석
  - 🙋 신입: 흐름표·흐름도 초안, 실제 대조

  - 🏢 고객사: 업무 설명, 확인

  - 🏢 고객사: 위험 수용 결정(경영진 승인)
- 보호대책 선정

## 9. 고객사 점검용 체크리스트

각 항목: **점검 항목** → 확인 방법 / 요청 증적 → 판정 기준

### ① 정보자산 (No 1~4)

- [ ] **No 1. 분류기준**: 정보자산 분류기준이 문서로 정해져 있다
  - 확인 방법: 문서 / 요청 증적: 자산 분류 기준
  - 판정 기준: 🟢 있음 · 🔴 없음
- [ ] **No 2. 자산 누락 없음**: 범위 내 자산(개발·클라우드·백업·보안시스템·외주 PC 포함)이 목록에 있다
  - 확인 방법: 문서·시스템 / 요청 증적: 자산 목록, 구성도, 콘솔 캡처
  - 판정 기준: 🟢 누락 없음 · 🟡 일부 누락 · 🔴 다수 누락
- [ ] **No 3. 보안등급**: 보안등급이 기준에 따라 합리적으로 산정되었다
  - 확인 방법: 문서 / 요청 증적: 자산 목록 등급 열
  - 판정 기준: 🟢 합리적 · 🟡 일부 부적절 · 🔴 기준 불일치
- [ ] **No 4. 최신화**: 자산 목록이 정기적으로 최신화된다
  - 확인 방법: 문서 / 요청 증적: 최종 확인일, 변경 절차
  - 판정 기준: 🟢 1년 이내·절차 있음 · 🟡 절차 없음 · 🔴 오래됨

### ② 흐름 (No 5)

- [ ] **No 5. 흐름도 일치**: 서비스별 개인정보 흐름도가 실제와 일치한다
  - 확인 방법: 문서·인터뷰·시스템 / 요청 증적: 흐름표·흐름도, 연계 정의서
  - 판정 기준: 🟢 일치 · 🟡 일부 누락 · 🔴 다수 불일치

### ③ 위험관리 (No 6~8)

- [ ] **No 6. 위험관리계획**: 위험관리계획(인력·기간·대상·방법·예산)이 올해 수립되었다
  - 확인 방법: 문서 / 요청 증적: 위험관리 계획서
  - 판정 기준: 🟢 5요소 · 🟡 일부 · 🔴 없음
- [ ] **No 7. 위험평가 수행**: 위험평가가 연 1회 이상, 관리적·기술적·물리적·법적 영역을 포함해 수행되었다
  - 확인 방법: 문서 / 요청 증적: 위험평가 결과보고서
  - 판정 기준: 🟢 충족 · 🟡 일부 영역 · 🔴 미수행
- [ ] **No 8. 경영진 승인**: DoA와 수용 위험이 경영진 승인을 받았다
  - 확인 방법: 문서 / 요청 증적: 승인 문서, 위원회 회의록
  - 판정 기준: 🟢 승인 · 🔴 미승인

## 11. 실습 과제 / 퀴즈

### 객관식

**Q1.** 인증기준 안내서 1.2.1의 결함사례에 해당하지 **않는** 것은?

① 인증범위 내 클라우드 자산 식별 누락
② 고유식별정보를 저장한 백업서버의 기밀성 등급을 (하)로 산정
③ 자산 목록에 자산명·용도·위치·책임자를 기재
④ 제3자로부터 제공받은 개인정보에 대한 자산 식별 누락

**Q2.** 위험평가에서 신입 컨설턴트가 맡기에 가장 적절한 업무는?

① 수용 가능한 목표 위험수준(DoA) 결정
② 위험 수용 여부 최종 승인
③ 갭 분석·점검 결과를 바탕으로 위협·취약점 목록 정리
④ 위험평가 방법론 선정

**Q3.** 인증기준 안내서 1.2.3이 위험관리계획에 구체화하도록 한 항목이 **아닌** 것은?

① 수행인력
② 기간
③ 예산
④ 심사원 명단

### 실습

**상황**: A사 인프라팀이 준 서버 목록과 인터뷰 결과다. 자산 목록 누락을 찾고 흐름표·위험 식별표를 작성하라.

**제공 자료**

```text
[A사 서버 목록 (인프라팀 제공)]
SV-001 회원관리 WAS / SV-002 주문관리 WAS / DB-01 회원·주문 DB / FW-01 방화벽

[인터뷰 결과]
- 개발 서버 2대(DEV-01, DEV-02)가 있고, 월 1회 운영 DB 일부를 복사해 테스트
- 클라우드 D사: 가상서버 4대(위 WAS·DB 포함), 오브젝트 스토리지 1개(주문 증빙 이미지: 이름·주소 보임), 백업 스토리지 1개(DB 일일 백업)
- 콜센터 B사는 A사 상담 시스템(웹)에 접속해 고객 이름·연락처·주문내역 조회, 엑셀 다운로드 가능
- 마케팅팀은 월 1회 회원 DB에서 이름·휴대전화를 추출해 E문자에 파일로 전송
- 고객지원팀은 반품 신청서(종이)를 받아 스캔 후 캐비닛 보관
- DLP·매체제어 솔루션 사용 중 (목록에 없음)
```

**과제**

1. 서버 목록에서 빠진 자산을 모두 찾아 4절 자산 목록 양식으로 추가하시오. (C·I·A·보안등급은 근거를 한 줄씩)
2. "회원 마케팅 문자 발송" 업무의 수집·보유이용·제공파기 흐름표를 `./2_산출물_양식/07_개인정보_흐름표.md` 양식으로 쓰시오.
3. 위 자료에서 위험 식별표(4절 양식)를 5행 이상 쓰시오. 관리적·기술적·물리적·법적 영역이 모두 들어가게 할 것.

**작성 양식**: 4절 자산 목록·위험 식별표, `./2_산출물_양식/07_개인정보_흐름표.md`
