# 템플릿 사용 안내

이 폴더는 `./chapters/` 아래의 모든 챕터가 똑같이 따르는 작성 규격을 정의합니다.

| 파일 | 용도 |
|---|---|
| [chapter_template.md](./chapter_template.md) | 챕터 본문 템플릿. 12개 필수 구성 요소의 순서·형식을 정의 |
| README.md (이 파일) | 파일명, 각주, Mermaid, 판정 표기, 퀴즈 규칙 |

---

## 1. 새 챕터를 만드는 순서

1. `chapter_template.md`를 복사해 `./chapters/{N}주차_{주제}/{NN}_{챕터명}.md` 경로에 저장합니다.
2. H1 제목을 `# {N}주차-{NN}. {띄어쓰기를 살린 챕터명}` 형식으로 바꿉니다.
3. 템플릿의 `{ }` 자리표시자를 모두 채우고, `<!-- 작성 가이드 -->` 주석은 지웁니다.
4. 12개 필수 구성 요소를 **순서를 바꾸지 말고** 모두 채웁니다. 해당 내용이 없으면 섹션을 지우지 말고 "해당 없음"과 사유를 적습니다.
5. 퀴즈 정답과 실습 모범 답안은 본문에 쓰지 않고 `./answers_and_explanations.md`의 같은 챕터 소제목 아래에 씁니다.
6. 아래 **작성 전 점검표**로 마지막 확인을 합니다.

---

## 2. 파일명 규칙

- 형식: `./chapters/{N}주차_{주제}/{NN}_{챕터명}.md`
- 띄어쓰기 대신 언더바(`_`)를 씁니다.
- 괄호, 마침표, 쉼표, 가운뎃점(·) 등 특수문자는 쓰지 않습니다.
- 하이픈(`-`)은 `ISMS-P`에만 씁니다.
- 파일 안의 H1 제목은 띄어쓰기를 살립니다. 예: 파일 `03_개인정보처리방침_진단.md` → 제목 `# 1주차-03. 개인정보처리방침 진단`
- README 목차 링크와 실제 파일 경로가 **글자 하나까지 같아야** 합니다.

---

## 3. 근거 표기(각주) 규칙

| 상황 | 표기 |
|---|---|
| `references/` 파일에서 확인함 | `[출처: 파일명, p.쪽, 조항·항목번호]` |
| 법령·고시 조문 (쪽수 대신 조문으로 특정 가능) | `[출처: 파일명, 제29조제1항]` |
| references에 없어 일반 지식으로 보충함 | `[출처: 일반 지식, 원문 확인 권장]` |
| references와 일반 지식이 다르거나 확인할 수 없음 | 본문에 `> ⚠️ 확인 필요: {무엇을, 왜}` 블록 |

- 각주는 GitHub 각주 문법 `[^1]`을 쓰고, 챕터 맨 끝 **각주** 절에 모읍니다.
- **쪽수는 문서에 인쇄된 쪽 번호**를 씁니다. PDF 뷰어의 쪽 번호와 다를 수 있습니다. (예: `개인정보의 안전성 확보조치 기준 안내서(2026.11).pdf`는 PDF 쪽 번호에서 8을 빼면 인쇄 쪽 번호)
- 파일명은 확장자(`.pdf`)까지 그대로 쓰고, **references 파일로 바로 열리는 링크**로 만듭니다. 파일명에 공백·괄호가 있으므로 경로를 꺾쇠 괄호로 감쌉니다: `[파일명](<../../references/파일명>)` (챕터 기준 경로. 산출물은 `../references/`, 루트 문서는 `./references/`). 파일명에 `[ ]`가 있으면 링크 텍스트에서만 `\[ \]`로 이스케이프합니다.
- 파일명이 길어도 앞부분만 쓰지 말고 **전체**를 씁니다. (링크가 깨집니다)
- 조문 번호, 인증기준 항목 번호·개수, 평가지표, 시행일은 **원문을 다시 열어 확인한 뒤**에 씁니다.

예시:

```markdown
접속기록은 1년 이상 보관해야 합니다.[^1]

[^1]: [출처: [개인정보의 안전성 확보조치 기준(개인정보보호위원회고시)(제2026-9호)(20260701).pdf](<../../references/개인정보의 안전성 확보조치 기준(개인정보보호위원회고시)(제2026-9호)(20260701).pdf>), 제8조제1항]
```

## 4. Mermaid 작성 규칙 (엄격 준수)

렌더링 오류를 막기 위해 **모든 노드 텍스트와 라벨을 쌍따옴표(`" "`)로 감쌉니다.** 언더바·괄호·특수문자가 없어도 예외 없이 감쌉니다.

| 대상 | ✅ Good | ❌ Bad |
|---|---|---|
| flowchart 노드 | `A["수탁사_점검 착수"]` | `A[수탁사_점검 착수]` |
| flowchart 엣지 라벨 | `-->\|"자료 미제출"\|` | `-->\|자료 미제출\|` |
| 다른 모양 노드 | `B{"증적 있음?"}`, `C(["완료"])` | `B{증적 있음?}` |
| subgraph 제목 | `subgraph S1["착수 단계"]` | `subgraph 착수 단계` |
| gantt 섹션·작업명 | `section "1분기"` / `"자료 요청" :a1, 2026-01-05, 5d` | `자료 요청 :a1, 2026-01-05, 5d` |
| sequenceDiagram 참여자·메시지 | `participant C as "고객사"` / `N->>C: "자료 요청 메일(D+0)"` | `N->>C: 자료 요청 메일(D+0)` |

추가 규칙:

- 노드 ID(`A`, `B1`, `N` 등)는 영문과 숫자만 씁니다. 한글은 따옴표 안의 텍스트에만 씁니다.
- 노드 텍스트 안에서는 쌍따옴표를 다시 쓰지 않습니다. 강조가 필요하면 `「 」`를 씁니다.
- 줄바꿈이 필요하면 따옴표 안에 `<br/>`를 씁니다. 예: `A["자료 요청<br/>(D+0)"]`
- gantt 날짜는 `dateFormat YYYY-MM-DD`로 고정합니다. 가상 일정이면 본문에 "예시 일정"이라고 밝힙니다.
- 챕터마다 Mermaid 다이어그램(flowchart 또는 gantt)을 **1개 이상** 넣습니다. 4주차-01은 gantt가 필수입니다.

## 5. 판정 표기 규칙

| 표기 | 판정 | 배경색 HEX (Excel·보고서용) |
|---|---|---|
| 🟢 양호 | 요구사항 충족, 증적으로 확인 | `#3cb371` |
| 🟡 부분 이행 | 일부 충족 또는 증적 불완전 | `#daa520` |
| 🔴 미흡 | 미충족 또는 증적 없음 | `#c35b5b` |
| ⚪ 해당 없음 | 적용되지 않음 (사유 필수) | `#808080` |

- 글자색은 지정하지 않습니다. 강조 배경색은 위 4개 HEX 코드만 씁니다.
- GitHub은 마크다운 안의 HTML `style` 속성을 표시하지 않으므로, 마크다운 표 안에서는 **이모지 + 판정 텍스트**로 표기합니다.
- 판정에는 반드시 **판정 근거(증적 파일명 또는 확인 방법)**를 함께 적습니다.

## 6. 퀴즈·실습 규칙

- 각 챕터에 **객관식 3문항 + 실습 1문항**을 둡니다.
- 객관식은 4지선다로, 오답 선택지도 현장에서 실제로 하는 실수를 바탕으로 만듭니다.
- 실습은 **가상 고객사(A사 또는 B기관) 자료를 주고 진단 결과를 쓰게 하는 형식**으로 만듭니다. 결과는 `./deliverables/` 양식에 쓰게 합니다.
- 정답과 해설은 본문에 넣지 않습니다. `./answers_and_explanations.md`에서 아래 형식으로 씁니다.

```markdown
## 1주차-03. 개인정보처리방침 진단
### 객관식
- **Q1 정답: ③** / 해설 / ①이 틀린 이유 / ②가 틀린 이유 / ④가 틀린 이유
### 실습 모범 답안
- 진단 결과 표 + 판정 근거
```

## 7. 작성 전 점검표

| 점검 항목 | 확인 |
|---|---|
| H1 제목이 `# {N}주차-{NN}. {챕터명}` 형식인가 | ☐ |
| 12개 필수 구성 요소가 순서대로 모두 있는가 | ☐ |
| 학습 목표가 3개 이내이고 "~할 수 있다"로 끝나는가 | ☐ |
| 설명 순서가 현장 비유 → 근거 → 수행 절차 → 신입 업무 → 오답노트인가 | ☐ |
| `📌 기초 개념 짚기`가 2~3줄 요약과 근거 조문만 담고 있는가 | ☐ |
| 모든 조문·항목·지표·시행일에 출처 각주가 있는가 | ☐ |
| 확인되지 않은 내용에 `⚠️ 확인 필요`를 달았는가 | ☐ |
| Mermaid 노드·라벨·작업명·메시지가 모두 쌍따옴표로 감싸져 있는가 | ☐ |
| 업무 분담표가 신입 / PM·선임 / 고객사 3열로 나뉘어 있는가 | ☐ |
| 처분·결함 사례에 출처(의결 연월, 보도자료 제목 또는 파일명)가 있는가 | ☐ |
| 오답노트가 3개 이상이고 ❌ / ✅ / 근거 3열 표인가 | ☐ |
| 체크리스트가 점검 항목 / 확인 방법 / 요청 증적 / 판정 기준 4열인가 | ☐ |
| 퀴즈 정답이 본문에 없는가 | ☐ |
| Windows 11 기준으로 도구·경로·명령어를 안내했는가 | ☐ |
